# Agent Desk

Agent Desk는 동일한 Mac에서 로그인한 Codex와 Claude Code를 업무 채널, 승인함, 후속 스레드로 묶는 1인용 로컬 AI 작업실이다. 일반 업무의 정리, 초안, 검토, 결과 비교에 사용할 수 있다.

[macOS 다운로드 및 활용 가이드](https://cm-jccho.github.io/agent-desk/)

## 시작

Node.js 24 이상과 Codex 또는 Claude Code가 필요하다.

### macOS ZIP으로 시작

1. Finder의 **다운로드**에서 `agent-desk.zip`을 두 번 클릭하고 `agent-desk` 폴더를 연다. 브라우저가 이미 압축을 풀었다면 해당 폴더를 바로 열면 된다.
2. 폴더 안의 **Start Agent Desk.command**를 두 번 클릭한다. 작업실이 기본 브라우저에서 열린다. 브라우저가 자동으로 열리지 않으면 `http://127.0.0.1:4877`에 접속한다.
3. 사용하는 동안 자동으로 열린 터미널 창을 유지한다. 종료할 때는 해당 창에서 `Control+C`를 누르거나 창을 닫는다. 이미 실행 중에 다시 실행하면 같은 작업실을 연다. 이전 배포본에서 업데이트할 때는 기존 터미널 창을 종료한 뒤 새 시작 파일을 연다.

macOS가 개발자 확인 경고를 표시하면 다운로드 주소를 확인한다. 해당 파일을 신뢰할 수 있을 경우 시스템 설정의 **개인정보 보호 및 보안 → 그래도 열기**를 사용할 수 있다. [Apple 지원](https://support.apple.com/ko-kr/102445)

### 소스에서 시작

이 저장소의 루트에서 실행한다. BtoB 작업공간에서는 `npm --prefix apps/agent-desk start`로 실행할 수 있다.

```sh
npm start
```

브라우저에서 `http://127.0.0.1:4877`에 접속한다. 터미널의 `Ctrl+C`로 종료한다.

## 기존 계정 연결

1. **엔진 설정**에서 Codex와 Claude Code의 CLI 로그인 상태를 확인한다.
2. 로그인이 필요한 엔진은 터미널에서 각각 `codex login`, `claude auth login`을 실행한 뒤 **연결 다시 확인**을 누른다. 이미 로그인한 CLI는 해당 세션을 사용한다.
3. 별도 프로필을 쓰는 경우 앱을 시작하는 환경에 `AGENT_DESK_CODEX_HOME` 또는 `AGENT_DESK_CLAUDE_CONFIG_DIR`를 지정한다. 지정값이 없으면 CLI 기본 프로필 또는 실행 환경의 `CODEX_HOME`, `CLAUDE_CONFIG_DIR`을 따른다.

앱은 CLI의 인증 여부만 확인하며 토큰이나 계정 이메일을 저장하지 않는다. 승인한 요청과 선택 자료는 지정한 엔진 제공사로 전달되고, 호출은 해당 계정의 사용량과 이용 조건을 따른다.

## 사용 흐름

- 채널에서 **받는 봇**을 고르고 메시지를 보낸다. 실행 상태와 결과는 같은 대화에서 확인한다. 파일이나 메모리를 보내려면 **자료 첨부**를 열고 **승인함**에서 보낼 내용을 확인한다.
- **봇 팀**에서 봇을 추가하거나 이름, 역할, 엔진, 모델, 자료 폴더를 수정할 수 있다. 모델 목록은 선택한 CLI 세션에서 읽는다. 기존 업무에는 등록 시점의 봇 설정이 유지된다. 폴더를 등록한 봇에는 32KB 이하의 UTF-8 텍스트 파일을 요청마다 하나씩 상대 경로로 지정할 수 있다.
- **메모리**에서 반복 사용하는 기준을 등록·편집·삭제한다. 업무에 선택한 메모리와 첨부 파일은 요청을 등록한 시점의 사본으로 저장된다. 이후 메모리를 편집하거나 삭제해도 이전 업무에 저장된 사본은 유지된다.
- 완료된 응답의 **이어서 요청**을 누르면 앞선 요청과 결과를 포함해 같은 봇에 보완을 맡기거나 선택한 다른 봇에게 검토를 맡길 수 있다.
- 실행이 실패하거나 중단되면 **다시 요청**으로 같은 내용을 새로 등록할 수 있다. 등록과 승인은 분리되어 있다.

처음에는 회의 메모를 붙여넣고 “결정 사항, 남은 질문, 다음 할 일로 정리해 줘”라고 요청해 보자. 응답 아래 **이어서 요청**을 눌러 다른 봇에 “실행 전에 확인해야 할 가정을 찾아 줘”라고 넘길 수 있다.

## 실행 구조와 운영 범위

`브라우저 → 루프백 HTTP 서버 → SQLite 실행 큐 → 엔진별 CLI → 업무 기록`

요청과 이력은 한 트랜잭션으로 저장된다. 일반 메시지는 보내기로 실행을 승인하고, 파일이나 메모리가 포함된 요청은 승인함에 등록한다. 동일한 등록 키와 중복 승인을 처리하며, 동시에 최대 2개 작업과 봇별 1개 작업을 실행한다. 재시작하면 승인된 실행 대기 업무를 계속 처리하고, 실행 중이던 업무는 중단으로 표시한다. 실행 제한은 3분이다. 강제 종료로 고아 프로세스가 생길 수 있으므로 운영 환경에서는 종료 신호를 전달하는 프로세스 관리자 사용이 필요하다.

기본 저장 경로는 macOS의 `~/Library/Application Support/Agent Desk`다. `AGENT_DESK_DATA`로 데이터 디렉터리를, `AGENT_DESK_PORT`로 포트를 바꿀 수 있다. 데이터는 로컬 SQLite에 평문으로 남으므로 운영체제의 사용자 계정과 디스크 암호화 설정에 의존한다.

현재 실행 범위는 텍스트 초안·분석·검토다. CLI의 기본 도구를 제한하며, 봇 폴더는 명시적으로 첨부한 파일의 읽기에 사용된다. 범위 확장이 필요한 항목은 코드 수정, 외부 발송·결제·예약, 조직 멤버별 권한, 서버 공개 배포, 모바일 페어링, 서명된 macOS 설치 패키지다. 서버는 IPv4 루프백에서만 연결을 수락하는 단일 로컬 운영자 모델이다.

## 검증

```sh
npm test
```

자동 테스트는 중복 승인, 스레드 연결, 재시작·저장 복구, 메모리와 파일 사본 고정, 폴더 이탈 차단, 취소·재요청, 로컬 요청 검증을 확인한다. 실계정 CLI 확인은 별도 임시 데이터베이스와 비민감 테스트 요청으로 진행했다.

공개 저장소의 `main`에 변경이 올라가면 GitHub Actions가 macOS ZIP을 만들고, 새로 압축을 푼 앱의 테스트를 통과한 뒤 GitHub Pages에 배포한다. 로컬에서 공유 파일을 만들려면 Mac에서 `node share/build-release.mjs`를 실행한다.
